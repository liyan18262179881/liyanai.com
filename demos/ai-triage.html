第 2 章 · 为什么做

2.1 市场背景与现状问题

国内院前急救现场长期依赖纸质检伤表，存在以下反复出现的核心痛点：

  • 双手被占用，无法手写记录；纸质表格易丢失、难追溯
  • 不同医护人员对同一伤情的分级存在主观差异，标准不统一
  • 急救指南和药物禁忌查询不便，影响处置质量
  • 纸质记录无法用于机构管理、质量分析和事后复盘

2.2 核心痛点

现场医护双手被占用无法记录，且分级依赖个人经验，同一伤情判断结果因人而异。

2.3 业务目标（MVP · 验证型）

  1. 验证生成质量：AI 分级建议准确率（与专家判断一致）≥ 85%
  2. 验证效率提升：现场录入耗时（扫码→提交）下降 ≥ 50%
  3. 验证使用意愿：试点机构医护 2 周内主动使用率 ≥ 80%

2.4 成功指标

指标名类型当前值目标值测量周期
AI 分级准确率质量—≥ 85%周
单次录入耗时效率~15分钟（纸质）≤ 7分钟周
医护主动使用率留存—≥ 80%双周
AI 建议修改率观察—观察值（用于优化）月

第 4 章 · 做什么

4.1 一句话定位

AI 智能检伤系统是一款面向院前急救场景的 AI 辅助检伤记录移动应用，帮助随车医护人员用语音替代手写、AI 辅助分级，全面取代纸质检伤表，数据可追溯。

4.3 核心功能详述

4.3.1 语音录入 + 体征双层提取

用户价值：免手持操作，口述即可完成记录，双手不离伤员。

技术流程：讯飞医疗版 ASR 实时转写 → MacBERT NER 毫秒级粗提取体征字段 → Qwen2.5-72B-Instruct 语义校验（处理「摸不太到脉搏→细弱」等口语歧义）→ 填入表单。

反例（非目标）：不做自由对话式改写；所有提取字段均可手动修正；未提及字段显示「未记录」，不自动猜测。

4.3.2 AI 分级建议

用户价值：减少主观判断误差，AI 建议有据可查，医护拥有最终决策权。

技术流程：体征 JSON + 检伤法 → RAG 检索 START/SALT 规则（BGE 向量化 + Milvus 检索）→ Qwen2.5-72B-Instruct 推理 → 输出等级 + 判断依据（≤20字）。响应目标 <3秒。

核心原则：AI 只给建议，医护点击「确认」或「修改等级」后才生效。系统同时记录 ai_suggest 和 final_grade，用于后续模型优化。

4.3.3 RAG 知识库推送

用户价值：实时提供处置建议和禁忌提示，提升现场处置质量。

技术流程：LangChain 编排 → BGE 向量化查询 → Milvus 检索 top-2 条目 → 绿色卡片显示，可收起，不干扰主流程。

知识库初始内容：START/SALT 规则、常见创伤急救指南、常用急救药物禁忌（20种），由医疗顾问审核后入库。

第 5 章 · 怎么做（技术实现意图）

5.1 AI 模型选型总览

层级选型用途选型理由
语音识别 ASR讯飞医疗版语音转写医疗术语识别率高；抗噪能力强；国内合规
信息粗提取MacBERT（NER）体征实体识别中文医疗语料预训练；毫秒级响应；速度快
语义校验 + 推理 + 生成Qwen2.5-72B-Instruct歧义消解 / 分级 / 病历国产私有化；等保合规；指令跟随稳定
Embedding 向量化BGE知识库向量化国内最强中文向量模型；完全开源
向量数据库Milvus知识检索开源私有化部署；实时检索性能好
RAG 编排框架LangChain串联 AI 链路生态最成熟；国产模型支持完善；上手快

5.2 AI 与规则的职责分工

决策由谁决定为什么
体征粗提取MacBERT（规则 + 模型）速度优先，毫秒级响应
口语歧义消解Qwen2.5-72B（AI）语义理解能力强，规则无法穷举口语表达
检伤分级建议AI + RAG 规则约束RAG 限制输出范围，AI 做推理，防幻觉
最终分级医护人员（人工）医疗决策不可完全交给 AI
SOAP 病历整理AI（Qwen2.5-72B）结构化输出，格式稳定
知识库检索匹配BGE + Milvus（规则）语义检索，确定性强

5.3 离线容灾方案

网络状态降级策略
弱网（2G/3G）ASR 降级本地轻量模型；LLM 使用缓存结果；RAG 使用本地缓存知识库
完全断网ASR 本地模型；AI 分级不可用，提示手动选等级；草稿全部存本地 SQLite
AI 服务异常显示「AI 暂不可用，请手动分级」；所有字段支持完全手动填写

5.4 技术栈总览

前端（移动端）React Native（iOS + Android 一套代码）
后端 APIPython + FastAPI（LLM/RAG 生态最成熟）
结构化数据库PostgreSQL（病历、任务、用户数据）
本地存储（离线）SQLite（草稿离线存储）
缓存Redis（会话状态、热点数据）
云部署阿里云医疗合规区（等保三级）

事项为什么规划

6.2 显式排除场景

  1. 不支持「AI 直接决定分级并自动执行」，必须医护确认
  2. 不支持院内交接预通知推送（二期）
  3. 不支持多机构数据互通
  4. 不做自动上报政府系统（合规边界未明确）

6.3 未来规划摘要

  • 转运路线规划 + 目标医院推荐 · 二期候选
  • 调度中心端 + 医院接收端 · 二期候选
  • AI 模型微调（基于积累的真实检伤数据）· 二期候选
  • 多机构协调 · 三期候选

第 7 章 · 合规与风险

7.1 法规与标准依据

  • 网络安全等级保护 · 等保三级，患者信息本地化
  • 《互联网信息服务深度合成管理规定》· AI 生成内容可追溯
  • 医疗器械软件（SaMD）· MVP 定位为「信息记录工具」，规避二类注册
  • 公司数据安全管理办法 · 患者数据不外泄、不出境

7.2 AI 特有风险

风险形态与防护
幻觉AI 可能给出与体征不符的分级。RAG 约束输出范围；医护必须手动确认；记录 ai_suggest vs final_grade
误判MacBERT NER 提取错误。所有字段显示后由医护校对；Qwen 做第二层语义校验
过度依赖医护跳过思考直接确认 AI 建议。UI 强调「AI 仅供参考」；记录修改率用于审计
隐私患者信息通过 AI API 处理。所有 LLM 调用经后端代理，患者数据 AES-256 加密，不出境
可用性AI 服务中断导致无法使用。离线容灾方案，核心流程支持全手动操作

7.3 责任边界声明

  1. 本工具产出为辅助建议，医护对最终检伤分级及处置决定负责
  2. 本工具不替代医疗专业判断，不具备诊断功能
  3. 本工具仅供授权机构内部医护使用，不对外开放
  4. AI 生成建议可能存在错误，医护须逐条核对确认
