案例 02 Agent App 应急救援

AI 电子胸牌系统

面向应急演练前线救援人员，设计集动态身份展示、任务状态、AI 动态提醒与一键求援于一体的智能 Agent App，2 个月独立交付完整 PRD 与原型。

结果 2 个月独立交付完整 PRD 与交互原型，通过 3 次应急演练实际验证
我的角色 需求分析、Agent 能力设计、交互流程设计、PRD 输出、项目统筹
面试亮点 把高压戴手套场景的 Agent 产品设计成大按钮、少输入、强反馈的可用系统

产品问题

应急演练现场不缺工具，缺的是能在高压下真正用起来的 Agent

应急演练前线救援人员面临身份识别慢、任务不透明、异常响应滞后三大痛点。现场戴手套、高压、弱网等条件下， 普通 App 根本用不起来。产品核心挑战是：在极端使用条件下，设计前线人员真的会用、敢用的 Agent 产品。

产品决策

MVP 聚焦前线手机端，用 Agent 工具链串联核心流程

  • 梳理前线人员在任务执行、状态上报、异常求援等场景的核心痛点，明确 MVP 聚焦前线手机端，不建设后端指挥端。
  • 设计 Agent App MVP 信息架构，规划动态身份卡、当前任务、当前位置、状态上报、SOP 查询和一键救援六大核心模块。
  • 定义 Agent 作为“个人任务与安全助手”产品定位，设计任务获取、SOP 查询、状态上报、请求救援等工具调用链路。
  • 针对高压、戴手套、低输入场景，设计大按钮、少输入、强反馈的操作方式，完善任务查看、状态上报和一键求援流程。

指标结果

用演练覆盖、核心流程稳定性和交付完整度衡量产品价值

北极星指标 弱网环境下核心流程完整可用
规模验证 3 次应急演练，覆盖 6 支救援队伍、60 台设备
交付完整度 独立输出完整 PRD，覆盖 P0/P1/P2 功能分级与验收指标
